## Independent reproduction protocol

With Elan, Git, and Python 3 available, run the following in Bash from a fresh clone of the public repository. Set `revision` to the full SHA of the edition under review. This uses the pinned Lean release and builds the project's dependencies from pinned sources with Lake's caches disabled.

```bash
set -euo pipefail
revision=f867a3016ed872747186faaa61d92ae5b12e6c82
git checkout --detach "$revision"
git rev-parse HEAD
test -z "$(git status --porcelain)"
test ! -e .lake
uname -sm
python3 --version
lean --version
LAKE_NO_CACHE=1 LAKE_CACHE_DIR= ./scripts/check.sh 2>&1 | tee ../prediction-depth-check.log
git diff --exit-code HEAD -- lean-toolchain lakefile.toml lake-manifest.json
```

For a cache-assisted replay, run `lake exe cache get` after the initial checks and then `./scripts/check.sh`. Record the cache source and check that `.lake/build` is absent before the project build. In either mode, a reviewer should retain the SHA, environment, cache policy, and full check log. A dated report identifying the reviewer and the theorem statements checked would substantiate independent review. The public CI record substantiates an automated rebuild. An external reviewer report has yet to be recorded.

The audit checks the logical axioms used by project declarations, including uses reached through imports. Verification relies on the pinned Lean toolchain and its kernel. A cache-assisted run also relies on imported compiled dependency artifacts. Rebuilding the dependencies from source removes that cache dependency. Comparing the formal definitions with the mathematical claims is a separate review task. [Logical foundations and trust boundaries](dependencies.md)

## Mathematical verification

- A has Lean proofs for the finite circuit construction, path-local conditions, arbitrary global state spaces, the uniform generator, and NC membership under the cost conditions. The uniform compiler accounts for copy gates during normalization. A binary time encoding alone does not give the required depth bound in input length.
- The standard B instance uses concrete machines and proved CVP completeness. The project proves uniform NC closure under general variable-length logspace reductions. The conditional result retains the explicit `P ≠ NC` assumption.
- C proves the integer bound `m ≤ b^d`, its logarithmic form, and finite witnesses using distinguishing assignments. The proof covers circuits with sharing.
- The OR example includes proved state semantics, a finite encoding, a concrete uniform generator, a fixed polynomial budget, exact optimal depth, and a matching lower bound for all shared De Morgan circuits. It covers time zero.
- The binary-field matrix example uses concrete XOR and AND circuits and gives depth, gate count, and complete description-size bounds. The propagation lower bound imposes locality on the predictor itself.
- The frozen-control family includes the coefficient formula for arbitrary initial controls, path compilation and decoding, logarithmic-depth upper bounds, a logspace-uniform generator, and a matching lower bound for the AND/OR example. [Frozen-control rules](frozen-pascal.md)
- The frozen-control classification characterizes when a single constant bounds all times. Varying guards have a logarithmic fan-in-two lower bound. For Pascal, the number of set bits in the time gives the exact depth with native XOR and determines the exact De Morgan depth with NOT charged. The optimum theorem is pointwise. The verified uniform classifier uses the separate `3p` construction. [De Morgan optimum](../PredictionDepth/FrozenPascal/PascalExactDepth.lean) · [Formalization cost and generator](frozen-pascal.md#proof-by-regime)
- The executable classifier agrees with the four semantic conditions. The uniform theorem gives language correctness, polynomial size, and regime-specific depth for the same generated family, and characterizes membership in standard uniform NC⁰.
- The transported-control model derives the finite-window conjunction from synchronous evolution on the infinite lattice, identifies the essential inputs exactly, and attains optimal depth with a linear-size construction. The lower bound covers binary networks with sharing. This is a per-time circuit result. [Lean theorems](../PredictionDepth/TransportedControl.lean)
- The ordered block compiler verifies the actual circuit's ordered semantics, depth, size, and complete logspace serializer. Additive control uses it to connect the dynamics to a linear-size uniform NC¹ predictor, and OR uses it with an executable finite template check. The additive example also executes the generic collision search on its time-two windows. [Compiler](../PredictionDepth/Complexity/BlockSummary.lean) · [Additive instance](../PredictionDepth/AdditiveBranching/Summary.lean) · [OR instance](../PredictionDepth/ORAutomaton/Summary.lean)
- With branching, uniform transport is reduced to frozen prediction by a reflected-frame rewire. Lean checks its correctness, depth and gate costs, and serializer through the directional reduction interface. [Reflected-frame instance](../PredictionDepth/TransportedBranching.lean)

For the statement review, compare the work-space measure, finite control, append-only output, and variable output length with the standard machine model. Check the query and clock encodings, the path-local hypotheses of A, and the explicit complexity separation used for B. For the frozen-control result, check that correctness, uniformity, size, and the branch-specific upper bound hold for the same family, and that the lower bound quantifies over all eligible predictors. For the transported-control example, check the finite-window projection and the scope of the per-time circuit bound. [Machine model](dependencies.md#standard-machine-model) · [Formal scope](requirements.md)
